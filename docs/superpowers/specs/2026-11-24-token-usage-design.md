# Token 用量统计和热力图

## 为什么

想看自己每天用了多少 token、一年里怎么分布。界面类似 GitHub 的提交热力图。

## 目标

- 累计用了多少 token、最近 30 天多少、最多的一天是哪天。
- 最近 53 周的每日热力图，点 / 悬停某天看当天总数、四项明细、Claude 和 Codex 各多少。
- 网页和 Mac 应用都有（功能写在 `web/`）。

## 不做

- 费用换算、按项目或电脑拆分、导出。
- 不统计没经过 Happy 的用量（终端里直接用的 Claude Code / Codex）。

## 方案选择

| 方案 | 取舍 | 结论 |
|------|------|------|
| A. 从 Happy 会话历史算：拉每个会话的消息，按回复日期累加 `usage` | Claude、Codex 都有；电脑离线也能看；会话不删就一直在。首次要拉全部消息，删掉的会话算不到（本地已算过的保留）；终端里直接用的算不到 | **选这个** |
| B. 通过机器 `bash` RPC 扫 `~/.claude/projects`、`~/.codex/sessions` | 最全，但电脑要在线；Claude Code 默认只留 30 天记录，热力图前面全空；依赖本地文件格式 | 不选 |
| C. 两者合并 | Happy 会话本身也是本地会话，要去重，复杂 | 不选 |

server 的 `POST /v1/usage/query` 不可用：CLI 每条回复都 upsert 同一行（`happy-server/sources/app/api/socket/usageHandler.ts`，键 `accountId + sessionId + key`），
只留最后一条回复的用量，日期是首次上报那天，而且只有 Claude 上报。

## 口径（已定）

- 总数 = 输入 + 输出 + 写缓存 + 读缓存，四项全算（和 ccusage 的 Total Tokens 一致）。热力图颜色也按这个总数。
- 所有会话都算，包括已归档的；Claude 和 Codex 都算；subagent 的用量也算。
- 一次回复拆成多条消息时只算一次（Claude 原始消息按 `message.id` 去重）。
- 按回复消息的 `createdAt` 的本地日期归到某一天。

## 界面（已定）

- 侧栏顶部「设置」旁边加图标，点开「用量」页，像设置页一样占住中间一栏。
- 顶部三个数：累计、最近 30 天、最多的一天（带日期）。旁边显示同步进度「统计中 34 / 80 个会话…」，数字边算边涨。
- 热力图：53 列（周）× 7 行（周一到周日），4 档颜色加「没有」。分档用有用量那些天的四分位。
  图下有「少 … 多」图例。窄屏横向滚动，默认滚到最右（最近一周）。
- 悬停或点击某天，下方显示：日期和星期、总数、读缓存 / 写缓存 / 输入 / 输出、Claude / Codex。

## 数据和缓存（已定）

- 逐个会话同步，参照 `lines.js` 的做法：先 `after_seq` 补新消息，再 `before_seq` 往前扫到头。
- 每个会话缓存在 `happy.usage.<会话 id>`：带版本号 `v`、已覆盖的 seq 区间、按天汇总的各项数字（按 agent 区分）。
- 首次打开用量页时同步全部会话；之后只补新消息。
- 会话从 server 上消失（被删）后，它的本地缓存保留，继续计入。
- 退出登录时清掉 `happy.usage.*`。

## 留给实现

- Codex 和新版 session 协议里 usage 具体在哪个字段、一条回复会不会带多次 usage，实现时对照 happy-cli 确认，并写进 `web/AGENTS.md`。
- 同步的并发、让路策略（是否给「改动行数」同步让路）、失败重试间隔。
- 数字格式（万 / 亿），颜色具体取值（沿用现有的 moss 绿色系）。
